# Microscope Panorama

Автоматическая сборка панорамы шлифа / аншлифа из видео, снятого через
микроскоп на iPhone (или любую другую камеру). Камера неподвижна относительно
микроскопа, перемещается предметный столик.

```
video.mov ──► круг поля зрения ──► keyframes ──► попарная регистрация
          ──► межпроходные совпадения ──► глобальная оптимизация графа
          ──► мозаика (multiband blending) ──► mosaic.tif + preview.jpg + CSV
```

## Установка

```bash
python -m pip install -r requirements.txt
```

Нужен Python ≥ 3.10. Зависимости: NumPy, SciPy, OpenCV, tifffile, PySide6
(последний только для GUI).

## Запуск

GUI:

```bash
python -m micropano            # или: python -m micropano --gui
```

1. **Open video…** — выбрать `.mov` / `.mp4`.
2. На вкладке *First frame* виден первый кадр и найденный круг (жёлтый —
   граница поля зрения, зелёный пунктир — реально используемая область).
   Круг можно поправить числами или мышью: **Shift+перетаскивание** — центр,
   **правая кнопка** — радиус, колесо — масштаб.
3. При необходимости поправить настройки (*Advanced settings* раскрываются
   отдельно).
4. **Build mosaic** — прогресс внизу, результат откроется на вкладке *Result*,
   подробности — на вкладке *Log*.

Командная строка:

```bash
python -m micropano video.mov -o out_dir
python -m micropano video.mov --detect-only          # только найти круг (fov.jpg)
python -m micropano video.mov --circle 960 540 610   # задать круг вручную
python -m micropano video.mov --blending feather --max-rotation-deg 2
python -m micropano --help                           # все параметры
```

## Выходные файлы

| файл | содержимое |
|---|---|
| `mosaic.tif` | полноразмерная панорама без уменьшения разрешения (RGB, тайловый TIFF, сжатие deflate; BigTIFF для > 2 ГБ) |
| `preview.jpg` | уменьшенный предпросмотр (по умолчанию ≤ 2400 px) |
| `frame_positions.csv` | `keyframe, frame, time_s, x, y, rotation_deg, quality, n_links, sharpness, segment, component, status` |
| `fov.jpg` | первый кадр с найденным кругом (CLI) |
| `log.txt` | журнал обработки, предупреждения (WARNING) и использованные настройки |
| `diagnostics/` | CSV и превью межсегментных связей (если трекинг разрывался) |
| `unlinked/` | отдельные TIFF и превью компонент, которые не удалось надёжно присоединить |
| `merge_data/` | keyframes и позы для ручного присоединения (создаётся, только если есть unlinked-компоненты) |
| `mosaic_merged.tif`, `preview_merged.jpg`, `frame_positions_merged.csv`, `merge_log.txt` | результат ручного присоединения (исходные файлы не перезаписываются) |

`x, y` — положение центра поля зрения кадра в пикселях `mosaic.tif`;
`quality` — средний коэффициент корреляции (ECC) по всем связям кадра;
`status`: `used` — кадр в `mosaic.tif`; `unlinked` — кадр в
`unlinked/component_<component>.tif` (x, y — в координатах этого TIFF);
`dropped` — кадр выкинут как ненадёжно зарегистрированный.

## Ручное присоединение unlinked-компонент

Если компонента не была присоединена автоматически, на вкладке *Result*
выберите её и нажмите **Attach to main mosaic…** (папку обработанного
результата можно открыть и позже — кнопка **Open result folder…**).

1. **Грубое положение** — на вкладке *Move / rotate* компонента лежит
   полупрозрачным слоем поверх основной мозаики: перетаскивается мышью,
   Shift+колесо или поле *Rotation* — небольшой поворот (±15°), стрелки —
   точный сдвиг (Shift — ×10). Альтернатива — вкладка *Corresponding
   points*: щелчками отметьте 2–3 одинаковые детали на основной мозаике
   (слева) и на компоненте (справа) в одном порядке и нажмите *Apply
   points* (1 пара — только сдвиг, 2–3 — сдвиг + поворот).
2. **Refine position automatically** — от ручного положения подбираются
   пары перекрывающихся keyframes и регистрируются по NCC/ECC (только по
   образцу) в окне *Search radius*; затем второй, узкий проход проверяет
   найденное положение на других парах. Показываются число подтвердивших
   пар, средний ECC, невязка, превью лучшей пары, а слой переносится в
   уточнённое положение. Положение считается подтверждённым, если согласны
   хотя бы `manual_min_pairs` (2) пар и большинство найденных.
3. **Merge — registered position** доступна только для подтверждённого
   положения (если после уточнения слой сдвинуть, нужно уточнить заново).
   **Merge — keep MANUAL position…** объединяет без подтверждения — после
   явного подтверждения; такие кадры помечаются `merged-manual` в
   `frame_positions_merged.csv`, а в `merge_log.txt` — `MANUALLY POSITIONED`.

Объединение пересобирает мозаику из исходных keyframes (тем же blending)
в `mosaic_merged.tif`; `mosaic.tif` и файлы в `unlinked/` не изменяются.
Компоненты можно присоединять по очереди — каждая следующая привязывается
к уже объединённой мозаике.

## Алгоритм

1. **Поле зрения.** Поэлементный максимум нескольких кадров → порог Otsu →
   наибольшая область → МНК-аппроксимация окружности по контуру. Точки
   контура на краях кадра игнорируются, поэтому круг, обрезанный кадром
   (типично для iPhone), находится правильно. Маска уменьшается на
   `mask_margin`, чтобы отбросить тёмный/размытый край.
2. **Маска.** Во всех расчётах (корреляция, ECC, резкость, blending)
   участвуют только пиксели внутри круга.
3. **Keyframes** (потоково, без загрузки всего видео в память). Анализируется
   `analysis_fps` кадров в секунду. Кадр отбрасывается как смазанный, если его
   резкость (дисперсия лапласиана) ниже `min_sharpness` × медианы соседних
   кадров. Почти одинаковые кадры (смещение < `keyframe_min_shift` × диаметр)
   пропускаются. Новый keyframe берётся, как только смещение стало
   достаточным; если текущий кадр уже не совмещается с keyframe, keyframe
   становится последний совместившийся кадр. Если трекинг потерян, начинается
   новый сегмент, который позже пришивается к остальным.
4. **Регистрация пары кадров** — модель translation `(dx, dy)`, при
   `max_rotation_deg > 0` — translation + малый поворот (rigid). Homography не
   используется.
   * грубо: маскированная нормированная взаимная корреляция (Padfield 2012)
     через FFT на уменьшенных high-pass изображениях — устойчива к
     изменениям освещения и не «видит» чёрный фон; тест неоднозначности
     (второй пик корреляции) защищает от однотипных участков породы;
   * точно: ECC (OpenCV) с маской на рабочем масштабе, субпиксельная точность;
     коэффициент корреляции — качество регистрации. Пара с низким качеством
     или с расхождением между грубой и точной оценкой отбрасывается.
5. **Соединение разорванных сегментов трекинга.** Ни одно отдельное
   совпадение не считается доказательством — это только гипотеза (anchor).
   * Сопоставление ведётся только по самому образцу: чёрный фон вокруг
     аншлифа и полоса шириной `link_edge_band` вдоль его внешней границы
     исключаются из NCC и ECC, чтобы длинный контрастный край не доминировал.
   * **Local gap recovery** (сначала, для соседних по времени сегментов):
     по скорости столика перед потерей трекинга предсказывается, где
     начинается следующий сегмент; последние `link_gap_keyframes` кадров
     одного сегмента и первые кадры другого регистрируются в расширенном окне
     (`link_gap_window` × диаметр + половина предсказанного смещения).
   * **Общий поиск** (для того, что осталось несоединённым): выборочные
     keyframes сегмента (`link_samples`) сравниваются со всеми кадрами
     основной компоненты, лучшие кандидаты уточняются ECC.
   * Связь принимается, если либо `link_min_matches` (3) **независимых**
     совпадений (разные несоседние кадры с обеих сторон) согласуются в
     пределах `link_tolerance`, либо **anchor подтверждён**: по его
     преобразованию предсказываются `link_verify_pairs` (4) соседних пар
     кадров обоих сегментов, они регистрируются локально (окно
     `link_tolerance`), и не менее `link_verify_min` (2) из них дают то же
     преобразование с малыми невязками.
   * Если подтверждений нет или две разные гипотезы подтверждаются
     одновременно — сегмент не присоединяется, выводится WARNING.
   * **Неприсоединённые компоненты не удаляются**: каждая (от
     `min_component_keyframes` кадров) оптимизируется отдельно и сохраняется
     как `unlinked/component_NN.tif` + `component_NN_preview.jpg`; в GUI их
     можно выбрать на вкладке *Result*.

   Диагностика: `diagnostics/segment_links.csv` (источник: global / gap /
   verify; пары кадров, NCC и второй пик, ECC, перекрытие, предполагаемое
   смещение сегмента, невязка, статус accepted / outlier / rejected /
   verify-failed) и превью перекрытия каждой пары (`link_*.jpg`: основной
   кадр — пурпурный, кадр сегмента — зелёный, совпадающая структура
   выглядит серой; контуры — области, участвовавшие в сопоставлении; для
   неподтверждённой пары показано предсказанное положение).
6. **Межпроходные совпадения.** По предварительным позициям ищутся кадры
   соседних проходов «змейки», чьи поля зрения перекрываются; поиск пика
   корреляции ограничен окном вокруг предсказанного сдвига (ещё одна защита
   от повторяющейся текстуры). Делается два раунда — второй с уточнёнными
   позициями.
7. **Глобальная оптимизация.** Все связи образуют граф; позы кадров
   находятся робастным нелинейным МНК (`scipy.optimize.least_squares`,
   soft-L1). Связи с невязкой > `outlier_threshold` × диаметр удаляются,
   задача решается заново. Кадры, оставшиеся без надёжных связей, в мозаику
   не попадают — лучше пропустить кадр, чем испортить мозаику.
8. **Плоское поле.** Медиана многих keyframes (снятых в разных местах
   препарата) аппроксимируется гладким 2-D полиномом — это профиль освещения
   (виньетирование микроскопа и камеры); кадры делятся на него. Чёрный фон
   вокруг образца в медиану не входит (иначе кадры у края аншлифа «затемняли»
   бы профиль с этой стороны и мозаика там пересвечивалась).
9. **Мозаика.** Рендер тайлами (память не зависит от размера панорамы) прямо
   в тайловый TIFF. Blending:
   * `multiband` (по умолчанию, лучшее качество) — швы проходят посередине
     между центрами кадров, низкие частоты смешиваются широко, высокие —
     узко: нет видимых границ и нет двоения;
   * `feather` — быстрое взвешенное смешивание по расстоянию до края круга;
   * `none` — без смешивания (для диагностики).

## Настройки

| параметр | по умолчанию | смысл |
|---|---|---|
| `min_sharpness` | 0.6 | минимальная резкость кадра относительно медианы соседних |
| `keyframe_min_shift` | 0.2 | минимальное смещение для нового keyframe (доля диаметра) |
| `expected_overlap` | 0.3 | ожидаемое перекрытие кадров соседних проходов |
| `max_rotation_deg` | 0 | допустимый поворот; 0 — только сдвиг |
| `analysis_fps` | 10 | частота анализа кадров |
| `blending` | multiband | качество blending: `multiband` / `feather` / `none` |
| `mask_margin` | 0.04 | доля радиуса, срезаемая по краю круга |
| `min_quality` | 0.5 | минимальная корреляция после точного совмещения |
| `max_peak_ratio` | 0.9 | порог неоднозначности (второй пик / первый) |
| `outlier_threshold` | 0.01 | порог выброса в графе (доля диаметра) |
| `flat_field` | true | коррекция виньетирования |
| `link_min_matches` | 3 | минимум независимых согласованных совпадений для присоединения сегмента |
| `link_tolerance` | 0.03 | допуск согласования совпадений (доля диаметра) |
| `link_edge_band` | 0.05 | полоса вдоль края образца, исключаемая при соединении сегментов |
| `link_verify_pairs` / `link_verify_min` | 4 / 2 | сколько соседних пар проверять вокруг anchor и сколько должно подтвердить |
| `link_gap_window` | 0.35 | окно local gap recovery (доля диаметра) |
| `link_diagnostics` | true | сохранять `diagnostics/` для межсегментных связей |
| `keep_merge_data` | true | сохранять `merge_data/` для ручного присоединения компонент |
| `manual_min_pairs` | 2 | сколько пар должно подтвердить положение при ручном присоединении |
| `save_unlinked` / `min_component_keyframes` | true / 3 | сохранять неприсоединённые компоненты отдельными TIFF |

Полный список — `python -m micropano --help` или раздел *Advanced settings* в
GUI. Настройки можно хранить в JSON (`--config settings.json`).

## Советы по съёмке

* Зафиксировать экспозицию и фокус (долгое нажатие на экран iPhone →
  «AE/AF lock»). Отключить HDR-видео (Dolby Vision), стабилизацию — по
  возможности.
* Двигать столик плавно; перекрытие соседних проходов — 20–40 % диаметра.
  Короткие остановки и смаз не страшны: такие кадры отбрасываются.
* Чем выше разрешение видео (4K), тем детальнее мозаика — масштаб не
  уменьшается.

## Тесты

```bash
python -m pytest tests
python tests/synthetic.py synth.mp4 --gt gt.csv     # синтетическое видео
python -m micropano synth.mp4 -o out
python tests/evaluate.py out/frame_positions.csv gt.csv
```

Синтетическое видео моделирует «змейку», обрезанный круг поля зрения,
виньетирование, шум, мерцание яркости, смазанные кадры и остановки столика;
опционально — повороты (`--rot`), резкие скачки столика с потерей трекинга
(`--jump`, `--jumps`), образец конечного размера на чёрном фоне (`--border`),
пониженный контраст (`--contrast`) и проходы без перекрытия (`--pass-step`). Во всех вариантах ошибка позиций кадров < 0.2 px.
